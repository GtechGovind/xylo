# Platform sandbox, OS permissions, and visible agent browser plan

Date: 2026-11-03. Status: proposed; implementation and cross-platform qualification outstanding.

## Goals and boundaries

- Provide fail-closed managed command isolation on macOS, Linux, and Windows. Keep Xylo's application-level approval rules separate from OS confinement. Never use a Job Object alone as a sandbox.
- Report real OS authorization state and request consent where the platform provides an API. Do not imply that display enumeration, a permission prompt, or a configured setting proves access.
- Deliver a full visible agent browser workspace in GPUI: the agent navigates, clicks, types, inspects pages and tests workflows while the user sees the same live tab and can explicitly take control. Obscura remains a supervised, headless engine rather than a separate native browser window; visibility does not prove renderer OS confinement.
- Preserve the current unrelated worktree changes. Implement and verify each phase independently; do not enable a Windows command fallback or publish preview frames into model-visible results or persisted history.

## Current evidence and feasibility

`crates/services/src/sandbox.rs:250-262` refuses Windows; macOS/Linux commands use the Node sandbox helper (`crates/services/sandbox-helper/run.mjs:156-175`). The Linux runtime warns, rather than errors, when seccomp socket protection is missing. `crates/services/src/sandbox.rs:655-679` does not validate inherited PATH directory ownership. `crates/build-bundle.rs:196-220` generates the macOS plist without a microphone purpose string. Desktop operations rely on xcap/enigo errors and refuse Wayland input (`crates/capabilities/src/desktop.rs:11-57`). Windows notification status lazily creates a registry key (`crates/notifications/src/platform/windows.rs:32-69`).

**Interactive panel is feasible, but not implemented by Xylo:** tagged Obscura v0.2.6 implements `Page.startScreencast`/`Page.screencastFrame`/`Page.screencastFrameAck` and `Input.dispatchMouseEvent`/`Input.dispatchKeyEvent` in its render-enabled CDP backend. Its `Page.captureScreenshot` already returns 1280x900 PNGs (`crates/capabilities/src/browser.rs:214-249,498-520`), and GPUI displays image previews (`crates/desktop/src/xylo/native_tools.rs:285-290`). Xylo's CDP client presently discards events while waiting for replies (`crates/capabilities/src/browser/cdp.rs:73-110`), so it cannot yet consume screencast frames. Agent and desktop helper own separate `CapabilityService` instances (`crates/engine/src/tools/mod.rs:242`), so the UI must receive frames from the agent worker's browser session. Obscura is launched with `--max-connections 1` (`crates/capabilities/src/browser.rs:178-211`); a second desktop CDP client is not the design. The existing worker protocol has an 8 MiB line limit (`crates/core/src/lib.rs:36`), not permission to enqueue an unbounded PNG stream. The current agent already has navigate/snapshot/click/type/wait/screenshot/close tools, but no visual panel, user handoff, native browser chrome or download tool (`docs/obscura-integration-plan.md:5-13`). The broker creates its own `CapabilityService` (`crates/engine/src/tools/mod.rs:242`) and shuts down root-turn capabilities on completion (`crates/engine/src/tools/mod.rs:2235-2253`), so an agent browser does **not** presently remain open across turns. Bundled runtime qualification is still outstanding (`docs/obscura-integration-plan.md:3-13`).

## Phase 0: acceptance contract and baseline

- Record the common policy: writable workspace and approved outside root; protected settings/credentials/control files remain inaccessible; default-off network; approved network follows existing broker semantics; denied launches never run unsandboxed; descendant cleanup is verifiable. Separate native LSP and browser sidecars from the managed-command guarantee.
- Add fixture-level policy tests, then run native integration probes on each supported OS, including symlinks, sockets, child processes, private-network and proxy bypass attempts. Record expected feature support by OS and kernel/backend; do not certify from Rust unit tests alone.

## Phase 1: harden existing macOS/Linux launcher

- Keep `sandbox-exec` on macOS and Bubblewrap on Linux. On Linux, treat unavailable required seccomp/socket isolation or incompatible namespace features as a sandbox-start failure, not a warning. If the pinned Node runtime cannot expose a strict option, add a verified preflight and explicit start-status failure, or replace that narrow launch component; never infer success from an exit code alone.
- Validate every directory and resolved executable on the unsandboxed launcher's PATH for ownership and unsafe writability, or construct a minimal allowlisted helper PATH. Preserve support for legitimate user-owned installations only with documented trust checks.
- Test blocked outside writes, protected reads, pathname and abstract Unix sockets, offline and approved network, launcher PATH substitution, failure statuses, parent exit, and cleanup on macOS/Linux CI. Fail closed when host prerequisites are missing.

## Phase 2: Windows managed commands

- Implement a Windows-specific backend behind the existing `prepare_coding_with_scope`/process-result contract. Use Windows **AppContainer** (evaluate the existing `windows-sys` bindings versus `rappct` for profile/ACL setup). Grant the AppContainer SID only required executable/dependency access, project and approved-root access, and isolated temporary storage. Keep credentials, private status files and protected settings outside its ACLs. Launch without network capability by default.
- Attach a Win32 Job Object for process-tree lifetime and resource limits; arrange launch/assignment so unconfined child execution cannot race before containment. Handle nested jobs, profile/ACL cleanup, cancellation and restart. If any isolation or job setup fails, report `NotStarted`; only then advertise Windows command tools. Do not treat restricted tokens or Job Objects alone as equivalent.
- `internetClient` is not a domain allowlist. Decide how an approved Windows command reaches a trusted network broker without enabling direct bypass; preserve private-network and local-binding semantics and denial reporting before claiming parity. If parity is not possible initially, keep Windows approved-network commands unavailable and say why.
- Add Windows host tests for file ACLs, network denial, descendants, start failure, profile cleanup and command advertising; test from a packaged application as well as CI.

## Phase 3: OS authorization and notification correctness

- macOS: add `NSMicrophoneUsageDescription` to the generated bundle plist and verify the **finished signed bundle**. Use AVFoundation authorization status/request for recording; CoreGraphics `CGPreflightScreenCaptureAccess`/`CGRequestScreenCaptureAccess` for capture; ApplicationServices `AXIsProcessTrustedWithOptions` for input. Consider `objc2-av-foundation`, `objc2-core-graphics`, and `objc2-application-services`, or small direct bindings if narrower. Request only on explicit user action; recheck after prompting, distinguish denied, not-determined and backend failure. Check whether signing/hardened-runtime entitlements are actually required for the shipping bundle; never assume a Rust crate grants TCC access.
- Linux X11/Windows: keep operation errors meaningful without presenting platform-independent TCC states. For Wayland, plan portal-mediated ScreenCast/RemoteDesktop consent with `ashpd`, PipeWire frames and portal input methods; capability/version-check the compositor, and continue to refuse unavailable global input rather than bypassing it.
- Windows notifications: separate read-only status lookup from registry registration; register only when enabling/posting requires it. Preserve macOS notification authorization and Linux daemon-availability distinctions. Add permission-state, denied-access, packaging and no-side-effect-on-query tests on relevant OSes.

## Phase 4: shared browser session and live view

- Move the browser session from the turn-scoped broker into a chat-owned worker lifetime with an explicit close/idle policy, bounded profile/storage and deterministic cleanup on chat close, worker death and app quit. Keep helper-agent sessions separate unless an explicit ownership rule allows sharing. A new turn must reattach to the *same* tab; no second browser is launched merely to view it. Tool permissions still apply separately on each new action.
- Follow the upstream [live-watching guide](https://github.com/h4ckf0r0day/obscura/blob/v0.2.6/docs/Watch-agent-sessions-live.md) where applicable: it uses adaptive `Page.captureScreenshot` polling for a **separate passive viewer** because screencast frames follow the session driving the page. Xylo instead intends to share the agent's owned CDP connection; qualify pinned Obscura v0.2.6's render-enabled `Page.startScreencast` on a real changing page before choosing it over the guide's proven polling approach. Refactor the worker-owned CDP client to multiplex replies and `Page.screencastFrame` events over its **existing authenticated connection**, acknowledge frames with `Page.screencastFrameAck`, stop the stream on unsubscribe, and cap frame rate, dimensions, encoded bytes and in-flight frames. Do not start a second CDP client or turn frame events into normal tool results. If the bundled screencast fails qualification, fall back to bounded, initially ~1 fps `Page.captureScreenshot` polling and label it a sampled preview. Never launch/navigate or create permanent screenshot artifacts just for preview; keep the explicit `browser_screenshot` tool unchanged.
- Route frames worker -> host -> owning desktop chat via a versioned, bounded, latest-frame-only transport. Choose either bounded image bytes with protocol-safe framing or host-managed private ephemeral files; verify ownership, generation, limits, cleanup and no arbitrary file paths. Drop stale frames on close, session replacement, cancellation, idle expiry, worker exit and chat switch. Preview data must not enter model observations, normal tool cards, transcript storage or logs; never expose the CDP token or listener.
- Render a dedicated GPUI browser pane/window with page image, address/title, loading and error indicators, current agent action and visible pointer/target highlight when available. Open it when the agent starts a browser workflow, let the user hide it without closing the tab, and stop sending frames when hidden. Keep web content framed as untrusted. Test mock-CDP event/reply interleaving, acknowledgement/backpressure, worker/host isolation and stale-frame rejection; gate on a bundled changing-page test, cross-platform packaging, bounded CPU/RSS and cleanup.

## Phase 5: agent testing and user takeover

- Keep the agent's existing browser actions on the shared session so navigation, CSS clicks/typing, waits, accessibility snapshots and screenshots update the visible pane without extra commands. Expand testing-oriented observations only after qualifying support in pinned Obscura (e.g. console exceptions, failed requests, navigation errors and assertions); report unsupported features explicitly. Provide action/status overlays rather than pretending every DOM action produces a physical cursor event. The agent must re-observe after navigation or user intervention; never assume stale selectors or a page's visual state.
- Add an explicit user-control mode with clear ownership: user input goes to the **same worker-owned session** via host-validated, bounded commands, serialized with agent CDP actions. Pause the agent's browser actions while the user controls the tab, then require a fresh snapshot/URL check when the user hands it back. Never silently race a user's typing or navigation, and never route browser input to OS-wide desktop input.
- Map GPUI clicks, pointer moves, scroll and keyboard/IME input to Obscura's tagged `Input.dispatchMouseEvent`, `Input.dispatchKeyEvent` and `Input.insertText` with correct scaling, letterboxing, viewport resize, focus and modifiers. Implement an address/navigation control only with the browser's existing URL validation, private-network policy and user-intent checks. Treat downloads, uploads, file pickers, new tabs, clipboard and password/autofill as separately scoped features, not implicitly supported by CDP input.
- For local-app testing, run the development server only with the existing explicit local-binding/network authorization; Obscura's current `browser_allow_private_network` opt-in broadly allows private/loopback networks, so require an explicit, visible user grant and do not silently enable it. A narrower session-scoped host policy would need separate design and validation.
- Test agent-driven form submission with visible frames, success/failure observation and assertions; same-tab continuation across turns; user click/type/scroll and takeover/handoff; focus, resize, navigation, backpressure and teardown on all target OSes. Keep the browser marked experimental until input semantics and site compatibility are validated. Obscura is headless: GPUI owns the window; Xylo does not acquire an upstream native browser window automatically.

## Release gates

No Windows command advertising before AppContainer and policy tests pass. No claim of complete Linux isolation if socket protection degrades. No microphone permission claim without a valid installed plist and runtime exercise. No claim of an interactive browser window before the CDP input and screencast path passes real runtime tests. Review Obscura sidecar confinement separately: its supervised process and loopback CDP are **not** an OS renderer sandbox. Publish a platform capability matrix and document any unsupported Wayland compositor or Windows network mode.
