# Native image generation

The Images page generates one image with an explicitly selected connection,
model and size. It can reuse an existing provider's OS credential reference, but
clears the chat model when copying a connection: an image-generation model must
be entered explicitly. **Generate image** starts a request; opening the page,
loading models and rendering previews do not call a generation endpoint or
install model weights. **Save image provider for agents** saves this separate
selection. There is no automatic provider/model fallback or automatic retry.

## Supported operations

| Selected protocol | Native request | Output handling |
| --- | --- | --- |
| OpenAI-compatible Images | `POST <selected API base>/images/generations`, explicit model, prompt, size and `n:1` | `data[0].b64_json`, image data URI, or a bounded provider-returned image URL |
| Gemini native GenerateContent | Explicit model's `:generateContent` endpoint, text prompt and `TEXT,IMAGE` response modalities | One inline image part from one completed candidate |
| Compatible local servers | The selected loopback OpenAI-compatible Images endpoint | Same validation and managed output contract; the server must actually implement the Images operation |

These are the operations documented in the primary
[OpenAI image-generation guide](https://developers.openai.com/api/docs/guides/image-generation)
and [Gemini GenerateContent image-generation guide](https://ai.google.dev/gemini-api/docs/generate-content/image-generation).
The selected model/account must support the operation. This slice does not
implement image editing, the OpenAI Responses image-generation tool, Gemini
Interactions, streaming partial images, or an embedded local diffusion backend.
ChatGPT plan sign-in for conversational Responses remains separate; this Images
operation requires its supported API credential. A deliberately configured anonymous HTTPS or local compatible server can
use no credential. A selected credential reference must resolve before dispatch. No paid account has been exercised during qualification.

OpenAI-compatible sizes exposed in the product are 256 square, 512 square,
1024 square, 1024×1536, 1536×1024 and explicit `auto`; actual model support is
reported by the chosen provider. Native Gemini accepts the three 1K aspect
ratios or explicit `auto`, with `imageSize:1K` for an explicit ratio. The app
never silently selects a larger output. The default selection is 1024 square.

## Native boundaries and durability

`workbench_core` owns request, provider, receipt and generated-image types.
`workbench_services::image_generation::ImageGenerationService` owns protocol
encoding, HTTP, decoding and durable receipts. Host imports/generation reserve
384 MiB of adaptive resource admission; native image decode is serialized across
processes by the same bounded/cancellable app-data lease used for attachments.
The UI owns only bounded form/request state and validated preview references.
Durable preparation, lease/reuse reads, hash validation, fsync/index commits and
provider JSON/base64 parsing run on blocking workers. HTTP remains asynchronous.
Each already-started durable phase retains the operation's file lease even if
its async caller is aborted, preventing false recovery during an active commit.

Provider configuration contains an OS credential reference, not a key. Auth,
cookie, key, token, secret, password, credential and session custom headers are
rejected. Endpoint URL credentials/query keys are rejected through the existing
provider validator. Provider response bodies, signed download URLs, raw prompts
and resolved secrets are absent from generation receipts and the recent index.
Requests retain only a SHA-256 fingerprint for identity checking. Agent prompts
remain part of the normal approved tool arguments/action journal.

| Boundary | Limit |
| --- | --- |
| Prompt | 16 KiB UTF-8 |
| Configuration | 32 KiB; at most 16 non-secret custom headers |
| Provider operation | One image; configured 1–600 second deadline |
| Provider JSON | 12 MiB, checked before/while reading |
| Encoded image/download | 8 MiB |
| Native image decoding/preview | The same 40 MP / 16,384-edge / 192 MiB decode and 256-edge preview limits as attachments |
| Active decode wait | 30 seconds, cancellable |
| Recent request index | 64 request IDs; UI/API returns at most 16 receipts |

Provider-returned URLs use a separate direct HTTP client with no provider auth,
cookies, environment proxy, redirect or retry. A selected same-origin loopback
server may return local HTTP output. Other origins require HTTPS and public
DNS addresses; checked addresses are pinned for the transfer. Private, loopback,
link-local, metadata and tunnel targets are rejected across origins. The app
never accepts a user/agent arbitrary remote image URL as generation output.

Generated bytes pass native sniff/decode validation and atomic managed import.
The original output is also atomically installed under
`data/artifacts/generated/REQUEST_ID.<format>`. The receipt binds its hash,
preview and typed attachment reference. Current-chat results enter the bounded
Artifacts view; the durable recent list remains the source for prior jobs.
**Attach to this message** adds the managed reference to the current draft only
when its conversation matches. Sending still requires the normal user action.

A request UUID has an exclusive cross-process lease. A duplicate UUID with the
same fingerprint returns its prior receipt; different arguments are rejected.
The submitted marker is synced before POST. There is no automatic replay.
Cancellation before dispatch is definite. Cancellation, timeout or transport loss
after dispatch preserves `outcome_unknown`, because the provider may complete or
charge after the connection closes. Server errors/HTTP 408 are also conservative
unknown results. Returned but invalid/unusable images are failed, with an explicit
possible-charge message. Native codec calls cannot be interrupted mid-call;
cancellation is checked between bounded stages and before artifact commits.

On restart, status reads recover abandoned submitted jobs as uncertain, while a
live job's lease protects it from false recovery. The Images page restores recent
receipts, previews and uncertainty. An uncertain selected result requires an
explicit acknowledgement that the provider was checked before allowing a new
request ID. This acknowledgement does not assert that the provider stopped or
refund a charge. Request status can be refreshed without resubmitting generation.

## Agent access

`image_generate` is an application-owned write tool using the same service. It
accepts only `prompt` and optional explicit `size`; agents cannot override the
saved provider, endpoint, model, credential or output path. A turn captures the
saved image provider so a settings change during approval cannot redirect the
operation. Approval shows the selected provider/model/protocol and prompt/size.
Read-only tasks and denied approvals never dispatch. The durable action UUID is
also the generation receipt UUID. Known failures are recorded as failed; uncertain
writes remain `outcome_unknown` and the existing action journal blocks replay.
Results expose managed references and artifact paths without inline image bytes.

## Qualification

All checks use native Rust, local HTTP servers and actual PNG output; no Python
or Node runtime, paid API, model-weight download or desktop permission prompt is
involved. Native clipboard tests use GPUI's test clipboard, so they do not establish
physical clipboard acceptance on each platform. Provider image quality, account
entitlements and real Linux/Windows desktop clipboard behavior remain unqualified.

Run from the repository root with `CARGO_INCREMENTAL=0`:

```sh
cargo +stable test -p workbench-services image_generation
cargo +stable test -p workbench-services attachments
cargo +stable test -p workbench-engine tools::image_generation
CARGO_TARGET_DIR="$PWD/target" cargo +stable test --manifest-path crates/desktop/validation/Cargo.toml --test image-generation-interactions
cargo +stable clippy -p workbench-services -p workbench-engine -p agent-workbench --all-targets -- -D warnings
```

The generation fixtures check both native protocols, actual saved output, bounded
HTTP/body/download handling, secret-free receipts/config, credential-free output
fetches, corrupt/private output rejection, cancellation, restart history and no
replay. Agent fixtures exercise real approval, frozen provider selection, actual
HTTP output and action-journal uncertainty. Native UI fixtures exercise restored
Images navigation, generate/preview/attach, Artifacts exposure, clipboard pixels,
late provider-load protection and stale/cancelled response isolation across chats.

Focused macOS fixture results (2026-10-25): generation services **13/13**, agent
image tools **3/3**, attachment services **7/7**, native Images target **10/10**
(two image interaction scenarios plus eight included regressions). Scoped strict
Clippy for services, engine and desktop all-targets passes. The service suite
includes single-thread runtime responsiveness under a contended durable commit
and forced async-abort retention of the writer lease. Full workspace, final
bundle and physical platform/account qualification are separate root checks.
