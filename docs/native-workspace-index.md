# Workspace catalogue and search

The workspace catalogue is a rebuildable private SQLite database under application data, separate from the conversation/action database and its executor. It contains all files admitted by the project's ignore policy. There is no file-count cutoff and no whole-project path vector, stamp map, or directory set in the host/UI.

The current format uses `<native-root-hash>.v1.sqlite` with SQLite `user_version=1`. Schema creation and the format marker commit together. Unversioned caches from earlier previews remain untouched; the new version builds alongside them. Nonempty unknown versions/layouts fail closed before schema or journal changes. An empty version-zero file is the only accepted interrupted-initialization state. There is no automatic cache deletion.

Traversal uses only `ignore::WalkBuilder.max_depth(1)`. SQLite's indexed `seen/kind/seeded/path` directory frontier replaces a recursive traversal stack. This matters because the underlying WalkDir can collect an entire wide ancestor when its descriptor limit is reached during deep recursion. Each shallow directory scan writes at most 512 entries per transaction. Root children are enumerated first; a requested folder can also be shallow-seeded while background discovery continues. An epoch check inside each transaction prevents a delayed folder request from writing into a later scan.

The writer has a 4 MiB SQLite page cache, disabled mmap, and file-backed temporary storage. At most two active folder/search jobs each have a 2 MiB page cache; their permits remain held until blocking work exits. Native notifications retain at most 4,096 distinct dirty paths and one wake. Overflow requests a streamed repair. Invalidation messages retain at most 256 paths and explicitly mark incomplete deltas, so the editor must recheck its own file rather than treating a bounded delta as exhaustive. Paths are platform-native BLOB keys (Unix bytes or Windows UTF-16 units); display text never determines identity.

Folder pages contain at most 500 immediate children, including directories, with revision/path keyset cursors. Counts are metadata. Pages during discovery are provisional and expose `indexing`; the completed revision invalidates provisional cursors/results. If a directory cannot be enumerated, the catalogue preserves cached children instead of asserting that unreadable files were removed.

Healthy native watching remains idle between events. Precise changes update only the named file or affected directory subtree. A coalesced remove/recreate uses a fresh marker and a bounded keyset pass to remove unseen descendants inside that subtree; directory-to-file replacement also removes its former children. Ignore-control changes and overflow request repair. A watcher setup/runtime failure is explicit (`watching=false`) and falls back to five-minute background reconciliation, with immediate manual refresh. Refresh errors back off rather than scheduling unconditional scans every minute in healthy mode.

Ignore handling preserves hidden-file inclusion, `.git` exclusion, `.ignore`, `.gitignore`, repository excludes, and global rules. Repository-aware shallow traversal enables the pinned ignore library's worktree `commondir` resolver while non-repository folders still honour `.gitignore`. Gitfile/commondir parsing follows pinned ignore 0.4 conventions; relative `gitdir` and missing `commondir` limitations are inherited. Changes to global or common-repository ignore files outside the selected root require Refresh; the app does not retain a watcher for every external repository encountered.

Content search uses the pinned grep libraries and reads 128 indexed paths at a time, releasing each SQLite read snapshot before file IO. Result limits bound a page, not project coverage. The 30-second work budget returns a path/line/byte continuation even with zero matches, so later files remain reachable and a large file need not be reread from its beginning. Unicode previews remain bounded. Binary, unreadable, and oversized-line inputs retain the text searcher's existing limitations; results do not establish a filesystem snapshot under concurrent edits.

Search opens an anchored directory authority and no-follow relative file handles. Internal file symlinks are first resolved inside the project and the resulting path is then opened through that authority; ancestor/final-file substitution cannot redirect the read outside it. Unix race fixtures execute this boundary. The actual Windows production reader is independently typechecked through `crates/runtime/validation/windows-workspace`; actual Windows filesystem/race execution remains unqualified, and UNC/network roots are unsupported by that reader. Existing editor open/save path checks are a separate boundary and are not qualified by these search tests.

These bounds describe implementation and focused fixtures. They are not a measured million-file RSS/latency result or a Rust-versus-other-runtime speed claim. The earlier live preview measurement belongs to its original executable/source; current live resource measurements require a rebuilt app.
