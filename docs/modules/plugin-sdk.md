# Plugin SDK (`sdk/plugins`)

## Purpose and boundaries

`sdk/plugins` is a **separate Cargo workspace** (`sdk/plugins/Cargo.toml`, members `guest`, `packager`, `examples/text-report`; edition 2024, Apache-2.0, `rust-version` 1.98) that gives developers Rust guest bindings, an offline component packager and a working example. It is not part of the desktop dependency graph. Installed components run inside the native Wasmtime host in `crates/capabilities` (see [capabilities.md](capabilities.md)); no Python, Node, WASI or external guest process is needed.

The SDK never installs, grants or runs a plugin. Installation independently checks the manifest rules and the exact supported ABI, so successful encoding does not prove install compatibility.

## Module map

| Path | Purpose |
| --- | --- |
| `sdk/plugins/wit/xylo.wit` | WIT contract, package `xylo:plugin@1.0.0`, world `plugin` |
| `sdk/plugins/guest` (`xylo-plugin-sdk`) | Guest bindings generated by pinned `wit-bindgen =0.57.1` |
| `sdk/plugins/packager` (`xylo-plugin-pack`) | Wraps a core module as a component and writes a package |
| `sdk/plugins/examples/text-report` (`xylo-text-report`) | Text statistics extension; `package.json` is its package template |
| `examples/plugins/echo` | Minimal hand-written WAT component (no SDK) |
| `crates/capabilities/src/plugins/*` | Host: `runtime.rs` (Wasmtime), `security.rs`, `catalog.rs`; `plugins.rs` tool surface |
| `crates/capabilities/examples/validate_plugin_sdk.rs` | Validation example against the real installed-plugin service |

## WIT contract (`xylo.wit`)

World `plugin` has three imports and one export, all synchronous from the guest's view (the host does async work behind the calls):

| Item | Signature | Requires |
| --- | --- | --- |
| import `read-text` | `func(path: string) -> result<string, string>` | `read_workspace`; bounded UTF-8 read under the workspace, links and private app data refused |
| import `write-text` | `func(name: string, text: string) -> result<string, string>` | `write_artifacts`; publishes a new artifact without replacing a file, returns the committed path |
| import `http-get` | `func(url: string) -> result<string, string>` | `https:<exact lowercase host>` (port 443); no credentials, cookies or redirects |
| export `run` | `func(input: string) -> result<string, string>` | none; input and output are UTF-8 text |

**An error from `run` does not undo already committed artifacts.** The package version identifies the contract; per the README the host checks the structural signature and supported imports rather than negotiating a version.

## Guest bindings (`guest/src/lib.rs`)

`wit_bindgen::generate!` with `world: "plugin"`, `pub_export_macro: true`, and a `bindings` module (doc-hidden). Public re-exports: `Guest`, `export`, `http_get`, `read_text`, `write_text`. Importing a binding grants nothing; every call checks stored grants.

```rust
use xylo_plugin_sdk::Guest;
struct MyPlugin;
impl Guest for MyPlugin {
    fn run(input: String) -> Result<String, String> { Ok(input) }
}
xylo_plugin_sdk::export!(MyPlugin);
```

Build as a `cdylib` for `wasm32-unknown-unknown`; avoid OS, socket, thread and clock APIs (no WASI adapter exists).

## Packager (`packager/src/main.rs`)

`xylo-plugin-pack <guest.wasm> <package-template.json> <new-output-directory>` (exactly three arguments).

- Reads the module (limit 16 MiB) and template (limit 32 KiB) with bounded reads.
- Template fields: `id`, `name`, `version`, `capabilities`, `budgets` (`deny_unknown_fields`).
- Encodes with `wit_component::ComponentEncoder` with `validate(true)` and no WASI adapter; an encoded component over 16 MiB is refused.
- Writes `component.wasm` and `plugin.json` (`format: 1`, `entrypoint: "component.wasm"`, SHA-256 of the component) into a **new directory**: `create_dir` fails if the path exists, files use `create_new`, and nothing existing is replaced. On failure the new directory is left for inspection. An invalid module creates no package.

## Example: text report (`examples/text-report`)

A `cdylib`/`rlib` using `serde` and `serde_json`. Template `package.json`: id `com.qurkos.xylo.text-report`, capabilities `read_workspace` and `write_artifacts`, budgets 16 MiB memory, 20 000 000 fuel, 10 s, 16 384 input bytes, 65 536 output bytes.

Input JSON: `{"path":"notes.txt","output_name":"notes-report"}`. It reads a UTF-8 file of at most `MAX_TEXT_BYTES` (16 KiB), reports bytes, Unicode scalar values, lines and alphanumeric word counts, keeps at most `MAX_UNIQUE_WORDS` (4 096) distinct words (and reports when hit), and publishes the statistics as a **new** text artifact. An existing `output_name` fails without changing the file. Per the README, it does not send content to a model or modify the source.

## Example: echo (`examples/plugins/echo`)

`plugin.json` (`format: 1`, id `com.qurkos.xylo.echo`, entrypoint `echo.wat`, **no capabilities**, budgets 8 MiB, 100 000 fuel, 5 s, 8 192 bytes in and out). `echo.wat` is a component in WAT text with one fixed memory page, a `realloc` that always returns offset 1024, and a `run` that returns the input string. The host loads WAT directly (`wat::parse_bytes` in preflight). Input is limited to 8 192 bytes; it is a contract demo, not an allocator template. Editing `echo.wat` changes the package identity, so update the `sha256` and re-review.

## Wasmtime host limits (`crates/capabilities/src/plugins`)

Manifest budgets (`PluginBudgets`, `crates/core/src/plugins.rs`; default 32 MiB, 10 000 000 fuel, 15 s, 256 KiB in/out) must satisfy `security.rs`: `memory_mib` 8..=256, `fuel` 1..=100 000 000, `timeout_seconds` 1..=60, `max_input_bytes` and `max_output_bytes` 1..=1 MiB. Name and version are bounded (version at most 64 chars, entrypoint path at most 512 bytes).

Enforced by `runtime.rs`:

| Limit | Value |
| --- | --- |
| Engine | Component model on, `consume_fuel(true)`, `max_wasm_stack` 512 KiB; one shared engine |
| Fuel | `store.set_fuel(budgets.fuel)`, async yield every 10 000 fuel |
| Memory | `StoreLimits.memory_size` = `memory_mib` MiB; also 1 memory, 4 tables, 10 000 table elements, 16 instances |
| Wall clock | `timeout_seconds`; error "Plugin exceeded wall-clock budget" |
| Output | `min(max_output_bytes, (config.max_output_bytes - 2048) / 6)` to leave room for JSON escaping; larger results fail |
| Input | Must not exceed `max_input_bytes` |
| Preflight | Expanded component at most 32 MiB; nesting at most 32; at most 10 000 functions; at most 1 000 000 instructions |
| HTTP | Own client, redirects disabled, 15 s timeout, body bounded by the output limit |
| Cancel | Parent cancellation, then 2 s wait for pending host effects |

Catalog (`catalog.rs`): registry at most 2 MiB, module at most 16 MiB, at most 64 packages, 1 GiB package storage, 4 096 operations. The linker supplies only the three root imports; the host validates the component interface before running (`validate_interface`). Grants come from stored user review, never from agent input; installed runs accept only `id`, `input` and `package_sha256`.

## Security

Permissions: `read_workspace`, `write_artifacts` and `https:<host>` grants are user-reviewed and revocable. Reads are limited to the selected workspace and refuse links and private storage; writes never replace files; HTTP has no credentials or redirects.

## Build and test (not run)

Per `sdk/plugins/README.md`, build the guest with `cargo build --locked --release --manifest-path sdk/plugins/Cargo.toml -p xylo-text-report --target wasm32-unknown-unknown`, then run `xylo-plugin-pack` with the `.wasm`, the template and a new directory. The README references `bash scripts/test-plugin-sdk.sh`, **but that file does not exist in this checkout**. Packager unit tests: `cargo test --manifest-path sdk/plugins/Cargo.toml -p xylo-plugin-pack`.
